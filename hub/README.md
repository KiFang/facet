# Facet Hub — хаб клубов для вуза или колледжа

Хаб разворачивается на сервере вуза один раз. После этого студенческие клубы подключаются сами, по
приглашению: выбирают шаблон (или загружают свою конфигурацию из редактора Facet OS) — и через минуту у
клуба работает своя учётная система: касса, инвентарь, мероприятия, отчёты, печатные формы.

```
clubs.univer.ru/                 главная: список клубов, «Подключить клуб»
clubs.univer.ru/hub/admin        кабинет вуза
clubs.univer.ru/c/<клуб>/        учётная система клуба (вход — только для актива клуба)
```

## Кто что видит

| | Актив клуба | Вуз (режим «только отчёты», по умолчанию) | Вуз (режим «полный доступ») |
|---|---|---|---|
| Записи клуба (люди, суммы, выдачи) | ✓ по ролям | — | ✓ через админку базы, каждое открытие в журнале |
| Сколько записей, новые за период, итоги касс и складов | ✓ | ✓ сводка и CSV | ✓ |
| Структура системы | меняет председатель из редактора | — | — |
| Подключение, приостановка, удаление клуба | — | ✓ | ✓ |

Каждый клуб — отдельная база PocketBase в своей папке. Снаружи открыт только прокси хаба; админка PocketBase,
вход суперпользователя, настройки и бэкапы через прокси закрыты (кроме режима полного доступа).

> Технически администратор сервера имеет доступ ко всем файлам на нём — это верно для любой системы.
> Политика «только отчёты» определяет, что вуз получает через хаб, и честно показывается клубам при подключении.

## Установка (Docker)

Нужен сервер с Linux, Docker и доменом (A-запись на IP сервера).

```bash
git clone https://github.com/kifang/facet.git && cd facet/hub
cp .env.example .env        # укажите почту и пароль администратора, домен
docker compose up -d --build
```

Откройте `https://<домен>/hub/admin`, войдите и создайте приглашение — ссылку отправьте председателю клуба.

Без домена (внутренняя сеть): в `.env` уберите `COMPOSE_PROFILES=https`, поставьте `HUB_BIND=0.0.0.0` и
`HUB_TRUST_PROXY=0`; хаб будет на `http://<сервер>:8080`.

Свой веб-сервер (Nginx, Traefik) вместо Caddy: проксируйте всё на `127.0.0.1:8080`, передавайте
`X-Forwarded-For` и `X-Forwarded-Proto`, разрешите тело запроса до 16 МБ и не обрезайте долгие соединения
(`/c/*/api/realtime`).

## Без Docker

```bash
npm ci && npm run build:hub
node scripts/fetch-pocketbase.mjs linux-x64           # или укажите свой бинарник в PB_BINARY
HUB_ADMIN_EMAIL=it@univer.ru HUB_ADMIN_PASSWORD=... HUB_DATA=/var/lib/facet-hub node hub/server.cjs
```

| Переменная | По умолчанию | |
|---|---|---|
| `HUB_ADMIN_EMAIL`, `HUB_ADMIN_PASSWORD` | — | первый администратор (при каждом запуске пароль из окружения становится актуальным) |
| `HUB_DATA` | `./hub-data` | состояние хаба и базы клубов |
| `HUB_PORT`, `HUB_HOST` | `8080`, `0.0.0.0` | где слушать |
| `HUB_PUBLIC_URL` | из запроса | внешний адрес для ссылок (`https://clubs.univer.ru`) |
| `HUB_TRUST_PROXY` | `0` (`1` в compose) | доверять `X-Forwarded-*` от обратного прокси |
| `HUB_CLUB_PORT_BASE` | `9100` | порты PocketBase клубов на 127.0.0.1 |
| `PB_BINARY` | `desktop/bin/<os>-<arch>/pocketbase` | путь к PocketBase 0.40 |

## Настройки хаба (кабинет → «Настройки»)

- **Кто может подключить клуб**: по приглашению (по умолчанию), по заявке с одобрением, любой.
- **Домены почты председателя**: например, только `@univer.ru` и `@student.univer.ru`.
- **Что видит вуз**: только сводные отчёты (по умолчанию) или полный доступ.
- **Черновые данные** при подключении, **загрузка конфигурации из редактора** (иначе только шаблоны).
- **Изменения, удаляющие данные, — только через вуз**.
- **Сторонние плагины с кодом** — по умолчанию запрещены: их код выполнялся бы на сервере вуза и в браузерах
  других клубов того же домена. Встроенные плагины (Telegram, автонумерация, журнал изменений) разрешены.
- Лимит клубов, строк импорта за раз, сколько копий хранить перед обновлениями; название, вуз, цвет.

## Как это работает

- Хаб **сам собирает** систему клуба из её описания (`club-schema.json`) тем же кодом, что редактор Facet OS.
  Готовые файлы от клубов не принимаются — только описание, которое проходит проверку.
- Первый вход в систему клуба — председатель с почтой и паролем из формы подключения. Пароль нужен
  только первой миграции и сразу удаляется с сервера. Остальной актив председатель добавляет сам.
- Председатель получает **ключ редактора**: в Facet OS «Публикация → Хаб вуза» он подключает к нему
  редактор и обновляет структуру своей системы (с просмотром изменений; удаление данных — только с
  подтверждением). Потерянный ключ вуз перевыпускает в кабинете.
- Перед каждым обновлением делается полная копия системы клуба (вместе с базой); откат — в кабинете вуза.
- При обновлении самого хаба порталы клубов пересобираются новой версией автоматически (структура и данные не меняются).

## Резервные копии

Все данные — в томе `hub-data` (`/data` в контейнере): `hub.json` и `clubs/<клуб>/system/pb_data`.
Простейший вариант — ежедневный снимок тома или `tar` папки при остановленном контейнере.

## Проверка

```bash
npm run build:hub && node scripts/hub-smoke.mjs --pb ./pocketbase
```

Сценарий проходит весь путь на настоящем PocketBase: приглашение, подключение, вход, закрытые пути, портал
в браузере, обновления, отклонение стороннего плагина, сводка, заявка с одобрением, перезапуск, удаление.
